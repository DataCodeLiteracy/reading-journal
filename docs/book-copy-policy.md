# 책 복사 시 데이터 정책

## 현재 동작

- **책 ID**: 사용자마다 같은 제목의 책이라도 `bookId`가 다릅니다.  
  예: 유저 A의 "루호" → `MY4TAOhEg9wHbF748gcD`, 유저 B의 "루호" → `HLLJ6ss3c35RtcpinnzV`
- **URL**: `/book/[bookId]/[user_id]` 이므로, 같은 책 제목이라도 유저/복사본마다 URL이 다릅니다.
- **독서 질문·구절 기록·독서 골든벨**: 각각 해당 **bookId**에만 연결됩니다.  
  → 한 유저가 책을 “복사”해 새 책을 만들면, 새 bookId에는 질문/구절/골든벨이 없습니다.

## 정책 선택지

### 1. 현재 방식 유지 (권장)

- **복사 시**: 질문·구절·골든벨은 복사하지 않음.
- **공개 의미**: “다른 사람이 **내 책 상세 페이지**에 들어왔을 때만” 해당 콘텐츠(공개된 질문/구절)를 볼 수 있음.  
  같은 제목의 다른 유저 책에는 보이지 않음.

**장점**

- 데이터 소유가 명확함 (내 책 = 내 데이터).
- 비공개가 “다른 유저 책에 안 보임”으로 일관되게 동작.
- 구현이 단순하고, 이미 현재 구조와 맞음.

### 2. 공개 시 “같은 제목 책”에 노출

- 누군가 질문/구절을 **공개**하면, **제목이 같은 모든 책**의 상세에서도 그 콘텐츠를 “공개 콘텐츠”로 모아서 보여줌.
- 복사는 하지 않고, “같은 제목 책”을 쿼리해서 공개된 콘텐츠만 표시.

**특징**

- 복제 저장은 없고, 조회만 제목 기준으로 확장.
- 구현 시: 책 제목(또는 정규화된 제목)으로 공개 질문/구절/골든벨을 조회하는 API·화면이 필요.

### 3. 복사 시 데이터까지 복사

- 책을 복사할 때 질문·구절·골든벨도 함께 복사.
- 복사본은 처음부터 원본과 같은 내용으로 시작하고, 이후 각자 수정 가능.

**단점**

- “비공개”가 “복사본에는 안 넘어감” 등으로 정해야 해서 정책이 복잡해짐.
- 중복 데이터와 동기화 이슈가 생길 수 있음.

---

## 권장안

- **1번(현재 방식 유지)** 를 권장합니다.  
  공개는 “내 책 페이지/탐색에서만 보인다”로 두고,  
  “제목이 같은 다른 유저 책”으로의 자동 복사나 자동 노출은 하지 않는 것이 단순하고 예측 가능합니다.
- 나중에 “같은 제목 책에서 공개 콘텐츠 모아보기”가 필요하면, 2번처럼 **조회만** 제목 기준으로 확장하는 방식을 검토할 수 있습니다.
